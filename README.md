## Overview

The project covers the full cycle of a slot title: math design and validation, engine development, presentation, account/wallet backend, fairness and compliance tooling, observability, and deployment. Commercial features ship built and tested but flag-locked off by default, so the public demo stays a fake-money product while the real-money capabilities remain one env var away. It is not a real-money gambling product.

## Features

### Gameplay
- 6×5 cluster-pays board with cascades, rendered in PixiJS 8 inside a Next.js shell.
- Samsara bonus meter and "Sky Opens" free-spins bonus with its own presentation flow.
- Runtime-selectable math profiles (RTP / volatility variants) backed by API settings and an audit trail.
- Win choreography system: tiered win presentation, multiplier cues, cascade chains.
- `/lobby` multi-game route driven by a typed game registry — adding a title is a registry entry plus a route.

### Fairness & compliance (flag-locked, built and tested)
- Server-authoritative spins (`POST /player/spin`): outcomes resolved server-side by the shared engine; the client never supplies a result. `PROVABLY_FAIR_ENABLED`.
- Provably-fair commit-reveal: per-player server-seed commitments (sha256), player-editable client seed, per-spin `HMAC-SHA256(serverSeed, clientSeed:nonce)` derivation, seed rotation with reveal, and an offline verifier script that reproduces any round.
- Responsible gambling: deposit/loss/session limits, cool-off, and self-exclusion, enforced server-side inside the round and deposit transactions. `RG_TOOLS_ENABLED`.
- Cloudflare Turnstile on registration with server-side verification, inert when unconfigured.
- Audit pack: [`docs/MATH_SPEC.md`](docs/MATH_SPEC.md) (RNG spec, audit contract, change control) plus reproducible 200k-spin PAR reports per math profile in [`docs/par/`](docs/par/), regenerated by one command.

### Player experience
- Fully responsive, board-first shell: phone portrait, tablet, near-square and landscape layouts each get a dedicated grid.
- Ritual log with session history and one-tap Session Analytics (RTP trend, win distribution, cascade histogram, CSV export) — tracked for guests and registered players alike.
- Guest mode works fully offline from the API; guests can convert to accounts without losing state; registered accounts get server-side wallet, ledger, and resumable game state.
- WebP-optimized art pipeline (symbols ~60 KB each), capped render DPR, adaptive graphics quality.

### Platform & operations
- Session-based auth (HTTP-only cookies, server-side revocation) with player/admin roles; helmet-hardened API, security headers on both web apps, Swagger and metrics opt-in for production.
- Structured JSON request logs with `X-Request-Id` correlation, Prometheus `/metrics`, liveness/readiness probes, and an importable Grafana dashboard with alert rules ([`docs/observability/`](docs/observability/)).
- 206 automated tests: engine RTP regression bands, provably-fair crypto vectors, RG enforcement matrix, security/validation e2e, real-engine server-spin integration.
- Dependency posture: 0 known high/critical production advisories, enforced by a CI audit job that fails on new findings.
- CI/CD: typecheck + lint + tests + Linux build gate, multi-arch (amd64 + arm64) Docker images published to GHCR — currently deployed on a Raspberry Pi behind Cloudflare.

## Architecture

pnpm workspace with three apps and three shared packages. The engine package is the single math source: the player shell resolves guest spins locally, the API resolves authenticated spins server-side (flagged), and the simulation/PAR harness reuses it offline. The API uses Prisma against PostgreSQL. Web apps proxy `/_api/*` to the API server-side, so the API origin never reaches the browser.

```text
player-web -> /_api proxy -> api -> game-engine -> PostgreSQL -> player-web presentation
```

| Component | Role |
|---|---|
| `apps/player-web/` | Next.js 15 player shell, PixiJS board, Zustand state, `/lobby`, localhost:3000 |
| `apps/admin-web/` | Admin panel, math profile config, RTP monitoring, localhost:3100 |
| `apps/api/` | NestJS 11 REST API, auth, sessions, wallet, rounds, fairness, RG, analytics, metrics, localhost:3200 |
| `packages/game-engine/` | Deterministic slot engine, math profile registry, simulation + PAR generators |
| `packages/shared-types/` | Cross-app TypeScript contracts |
| `packages/ui/` | Shared UI component package |

## Setup

```bash
git clone https://github.com/wannabexaker/The_Eye_in_the_Sky
cd The_Eye_in_the_Sky
corepack pnpm install
```

PostgreSQL must be running. Copy the env examples and set local secrets:

```bash
cp .env.example .env
cp apps/api/.env.example apps/api/.env
```

Then run API migrations and seed only if local seed accounts are configured:

```bash
corepack pnpm --filter api prisma:migrate
corepack pnpm --filter api prisma:seed
```

## Development

Fast local path when Docker is available:

```bash
corepack pnpm dev:full
```

This starts PostgreSQL, generates the Prisma client, applies migrations, seeds configured local accounts, and runs the API, player, and admin apps together. On Windows, `start-game.bat` does the same in three terminal windows.

```bash
# Terminal 1 - API
corepack pnpm dev:api

# Terminal 2 - Player shell
corepack pnpm dev:player

# Terminal 3 - Admin panel
corepack pnpm dev:admin
```

| App | URL |
|---|---|
| Player | `http://localhost:3000` |
| Admin | `http://localhost:3100` |
| API | `http://localhost:3200` |

Math tooling without starting the apps:

```bash
corepack pnpm simulate      # long-run RTP simulation
corepack pnpm par-report    # regenerate docs/par/ PAR sheets (200k spins, seed 1337)
```

Run the full build only after stopping dev servers:

```bash
corepack pnpm build
```

CI (`.github/workflows/ci.yml`) runs typecheck, lint, unit tests, API e2e, a full Linux build, and a production dependency audit (fails on high/critical) on every push and pull request.

## Deployment

`.github/workflows/build.yml` builds and publishes per-app Docker images to GHCR on every push to `main` and on release tags (`v*`), for both `linux/amd64` and `linux/arm64`. Production runs from `docker-compose.prod.yml`:

```bash
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
```

The reference deployment is a Raspberry Pi behind a Cloudflare tunnel serving [eye.olamov.com](https://eye.olamov.com). Portable deployment guide: [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md). Feature flags and day-2 operations: [`docs/OPERATOR_GUIDE.md`](docs/OPERATOR_GUIDE.md).

## Notes

- Do not run `pnpm build` while `pnpm dev:*` is active. The player build guard aborts when port `3000` is busy to avoid `.next` cache corruption.
- On Windows, standalone Next builds may compile and then fail on symlink creation with `EPERM`. Enable Windows Developer Mode or run build signoff in Docker/WSL/Linux; do not remove `output: "standalone"` to work around it.
- Seed credentials are local-only. Keep `PLAYER_SEED_*` and `ADMIN_SEED_*` blank in committed examples and set them only in ignored local env files.
- The provably-fair scheme changes only the engine's seed source (HMAC commit-reveal instead of `crypto.getRandomValues`), not the RNG itself, so certified RTP/volatility characteristics are preserved. Scheme details: [`docs/PROVABLY_FAIR.md`](docs/PROVABLY_FAIR.md).
